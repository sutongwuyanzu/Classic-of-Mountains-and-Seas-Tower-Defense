# S07 Steam Cloud 同步范围预研

最后核对：2026-09-19。本文是未来 Steam Auto-Cloud 的数据范围决策，不会修改 Steamworks 后台、现有存档路径或本地加载顺序。

## 结论

若后续通过真实 AppID 的 S06 原型，优先使用 **Steam Auto-Cloud**，并且第一版只同步一个已验证的进度文件：`save-v2.json`。

严禁把 Electron 的整个 `app.getPath('userData')` 目录映射到 Cloud。该目录可能包含 Chromium 数据、GPU/设备配置、缓存、日志和临时文件，不属于玩家跨设备进度。

## 当前持久化事实

| 文件/位置 | 当前用途 | Cloud 第一版处理 |
| --- | --- | --- |
| `userData/save-v2.json` | `src/main.js` 的进度、成长、关卡完成、音频偏好与波次检查点权威桌面存档；由 `save-store.cjs` 原子写入 | **同步**；实际目录映射以目标 AppID 的用户数据路径为准 |
| `userData/save-v2.json.bak` | 同机主文件损坏时的有效回退副本 | 不同步；云端主文件必须先通过结构与版本校验，不能让旧备份反向覆盖 |
| `userData/*.tmp` | 原子写入中的短生命周期临时文件 | 不同步 |
| `userData/achievements.json` | 目前只由主进程记录本地勋章解锁；游戏加载进度不读取它 | 不同步；Steam 成就接入后以平台状态和主进度为准，不能同步两套互相竞争的勋章来源 |
| 浏览器 `localStorage` | 旧版本/浏览器回退副本 | 不由 Auto-Cloud 同步；接入时须防止旧本地时间戳覆盖已下载的 Cloud 存档 |
| Chromium 缓存、GPU/窗口/日志数据 | 设备或运行环境状态 | 不同步 |

`save-v2.json` 当前写入前会验证 JSON、保留有效 `.bak` 并进行同目录替换；这满足 Cloud 前的本地完整性基础，但不代表已经解决跨设备冲突。

## 尚未通过的前置条件

1. **账号识别**：现有 `steamShell.platform` 恒为桌面 bridge 标识，无法判断真实 Steam 用户。S06 原型必须先提供主进程得到的 Steam 初始化和账号状态。
2. **加载优先级**：当前 `loadSave()` 会比较 Electron 存档与 localStorage 的 `savedAt`。启用 Cloud 前必须改为“已验证的 Cloud/桌面主档优先，旧 localStorage 只作为明确迁移候选”，不能自动按时间戳覆盖。
3. **首次迁移**：若云端无档而本机有有效旧档，可在用户确认后上传一次；若两边均有有效档而内容不同，必须显示可理解的时间/关卡摘要并由用户选择，禁止静默合并或覆盖。
4. **版本兼容**：未来版本号高于当前解析器的存档不得被旧客户端写回；冲突和解析失败必须保留两份文件供恢复。
5. **后台约束**：实际 Auto-Cloud 根目录、文件名、大小配额和跨平台规则必须按真实 Steamworks AppID 后台配置确认；本文不猜测数值或路径。

## 真实验收矩阵

完成 S06 后，再在独立测试环境中验证：

1. 账号 A 在机器 1 保存、正常退出并同步；机器 2 下载后能继续同一进度。
2. 机器 1、2 离线产生分叉时，客户端冲突选择可见且选择结果不被 localStorage 反向覆盖。
3. 同一台机器切换账号 A/B 时不串档；旧本地档不会自动导入所有登录过的账号。
4. 删除或损坏云端主档时，本地有效存档和 `.bak` 不会被清空；恢复路径清晰。
5. 重装后的首次启动、候选包升级和回退各验证一次；`.tmp`、缓存、日志和设备设置均未同步。

在上述测试完成前，商店页不得宣称 Steam Cloud。
