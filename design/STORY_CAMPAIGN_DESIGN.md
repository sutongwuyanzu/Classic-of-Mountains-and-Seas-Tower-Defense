## 2. 世界观、主题与神话边界

### 2.1 核心设定

五境古印原本彼此相应，让山海之息流转、浊气得以消解。古印逐渐失去联系后，浊气淤积，循水脉与裂隙侵染生灵。异兽先失去本识，继而循古印的灵息冲击封印；封印若毁，浊气便涌向其后的生灵聚居之地。

失联是长期失养、地脉变迁累积的结果，不另设幕后黑手。前四关分别恢复各境的局部联系，第五关接通最后一环，恢复整个循环。守关是为古印稳定争取时间，不增加计时仪式、采集或修复操作。

玩家称“守渊者”，持有残缺山海图谱。图谱承载白泽保留下来的清醒意识与妖灵灵契，不把万物囚禁在书里。召灵是借来愿意应契的化身，现有抽卡、升级与羁绊条件不变。玩家本身不成为新战斗单位。

每境一枚主印，赤焰主印由两处阵眼共同维系；地图上的“归位”表示恢复联系，不是收走石碑。五枚“归名印记”只展示章节通关进度，不占背包、不消耗、不提供属性。

“本识”是异兽仍能认出自己与同伴的意识。“识影”是被剥离、可以受浊气操纵的映影。每个新词先用具体画面或对白解释，不在开场集中灌输术语。

### 2.2 情感主线

开场以幽都封印后方的一盏村灯建立具体保护对象，不安排需要护送的村民单位。第一关玩家先救眼前的人；第二关发现攻击自己的异兽也在求救；第三关认识到只压制异兽无法解决灾变；第四关完成白泽救援；第五关让五境恢复联系。

终章仍以村口亮灯、异兽各归其路收尾。众灵共守是玩家现有阵容与结算画面的情感表达，不是召来一队额外援军。五关解决本篇灾变，不用“真正的幕后黑手才刚醒来”否定这次胜利。

### 2.3 角色与口吻

| 角色 | 功能 | 表达方式 | 实施约束 |
| --- | --- | --- | --- |
| 守渊者 | 玩家投射，负责选择与行动 | 主体不长篇发言；以“守印”“启程”表达行动 | 不新增可操作英雄、不画固定正脸 |
| 卷中余音 | 图鉴与章前题记的栏目名 | 简短书面语，古籍或原创都标明来源性质 | 不做实时发言者，不抢白泽的引导职责 |
| 白泽 | 从第一章起陪伴，第二章回收识影，第四章回归本体 | 先冷静务实，逐渐承认误判，最后坦率信任玩家 | 使用现有身份与外形；不入卡池、不提供技能或属性 |
| 浊气 | 古印失联后积累的灾变 | 以局部墨痕、紊乱水流与束缚表现 | 不拟人成幕后黑手，不加入反派独白 |
| 同行妖灵 | 玩家抽出的队伍 | 通过守护姿态和战斗建立联系 | 不要求指定抽卡结果，不替所有妖灵配长对白 |

白泽的变化应可辨认：第一章只知道必须先守印；第二章通过被救回的识影恢复部分记忆；第三章读懂水脉与古印关系，承认先前所知有限；第四章本体获救；第五章与玩家共同见证修复，而非施法替玩家取胜。

不要把它写成明知真相却故意隐瞒、让玩家白打三关。第四章战斗中短暂失联只是对白静默，章后已经救回；第五章解决山海失衡，不再次延后救援。

### 2.4 古籍依据与原创范围

这是**取材于山海神话的原创故事，不是《山海经》原文剧情复述**。来源页可放入图谱或制作说明，不在战斗中强迫阅读。

| 元素 | 依据与边界 |
| --- | --- |
| 幽都、黑水 | 《山海经·海内经》记有幽都之山与黑水，可用于第一章的环境意象。游戏中的洞窟、古印和事件为原创。[原文](https://zh.wikisource.org/zh-hans/山海經/海內經) |
| 昆仑与守门之兽 | 《山海经·海内西经》的昆仑、开明意象可启发第五章石阶与门阙，但不把“天庭云阶”宣称为原文地图。[原文](https://zh.wikisource.org/zh-hant/山海經/海內西經) |
| 饕餮形象 | 游戏采用广义中国神话中的饕餮形象；浊气借其显形为原创设定。不要将《北山经》狍鸮的记载直接写成饕餮传记。[原文参照](https://zh.wikisource.org/zh-hans/山海經/北山經) |
| 白泽识万物 | 《云笈七签》卷一百收录黄帝遇白泽、记录精怪的相关叙事；这是后世文献材料，不是《山海经》直接记载。[原文](https://zh.wikisource.org/wiki/雲笈七籤/100) |
| 补天意象 | 女娲炼石补天可参照《淮南子·览冥训》。五境古印、归名仪式及本作年代关系并不来自该段原文。[原文](https://zh.wikisource.org/zh-hans/淮南子/覽冥訓) |

不要把五境印记硬解释为原典五行体系，也不要给后世“龙生九子”故事加上未经核对的《山海经》出处。第一版无需神话百科式解释，避免旁支抢走主线。

本篇不依赖“绝地天通”、归墟或混沌七窍才能成立，因此不强加相关年代与设定。后续若引用归墟的无底大壑叙述，应标《列子·汤问》；混沌无七窍故事应标《庄子·应帝王》，不能混标《山海经》。参考：[《列子·汤问》](https://zh.wikisource.org/zh-hans/愚公移山)、[《庄子·应帝王》](https://ctext.org/text.pl?if=gb&node=2769&show=parallel)。

每章最多 1–2 处古文，不是必须凑满。第 4 节提供的章前题记全部是本作原创，不加古籍引号或伪造出处；以后替换为古文需逐字核对来源并补白话解释。

情感节奏依次为：承担责任、建立信任、理解灾源、不舍同伴、共同守护。每关只新增一个主要认识，不以增加设定名词代替推进。

### 3.1 首领连续性的解释

- 第一关饕餮：浊气包裹的“侵蚀之形”。正式胜利后呈现片刻清明与侵蚀散去，不声称已杀死全部凶兽或消灭灾源。
- 第二关白泽：被剥离、操纵的“缚识之影”。图谱中的清醒意识一直能传声；胜利让识影回归、恢复部分记忆，本体仍未脱困。
- 第三关饕餮：“浊潮之形”，表现沿水脉扩散的侵蚀。沿用同一战斗定义，不引入新的复活或继承机制。
- 第四关白泽：本体外覆的“焚识之影”。战胜后外壳散去、白泽显现；剧情不描述为杀死白泽。
- 第五关饕餮：“聚浊之形”，浊气借现有饕餮形貌汇聚，不是新的物种或幕后人格。击散后本识回归仅在结算画面出现，不分阶段掉出单位。
- 其他波次出现的白泽使用“白泽·缚识影”等上下文副名解释为映影；不把每次精英战都写成白泽本人登场。

副名只属于展示元数据，不替换敌人 ID、伤害规则、复起条件、图谱键或掉落。

“救回本识”是胜利叙事，不新增敌人俘获、救援进度或非致命伤害判定；原有击破、得分、奖励照常结算。白泽和饕餮仍使用原战斗表现，仅在正式结算后展示侵蚀散去。普通消散光点若制作，也只能复用表现层预算，不能成为实体或拾取物。

## 4. 可直接使用的剧情文案

### 4.1 文案显示约定

- 以下场景编号是交付与测试用 ID，不显示给玩家。
- 每条对白独立一屏或一页；移动端每页最多三行，溢出拆页，不把整段缩成小字。
- 正文默认完整出现；不强制逐字打字。推进由玩家点击，避免阅读时间不足。
- 片头和章前对白每场约 2–3 页；首轮额外阅读目标约 2–4 分钟，是设计预算，不是实测结果。
- 战斗短句只在不遮挡战场的位置显示一次，约 3–4 秒，无弹窗、无暂停、无队列积压。

- 白泽只是给现有教程增加署名与少量回应，不替换已经明确的操作指令，不改变教程触发、等待条件或整备时长。

- 羁绊仍由实际阵容条件激活；图鉴可以解释“旧盟”，不出现“过了本章所以永久激活羁绊”。
- 回看章节的战后画面属于故事记录，界面不重弹实际获得窗口，不重复播放数值增长。

## 5. 玩家流程与进度规则

### 5.1 入口与循环

主线入口 -> 山海卷地图 -> 当前推荐章 -> 章前 -> 原有整备/教程 -> 战斗 -> 原有胜负结算 -> 章后 -> 地图高亮下一章。

- 已有本局断点时，“继续守关”优先保留；不能因为新增“继续主线”诱导覆盖存档。
- 主线地图增加五个节点，但不把原有选关界面重复造一套复杂设置页。
- 每章节点显示地图名、章节名、通关印记；难度设置复用现有控件。
- 第一次主线默认简单。若用户主动选择其他已解锁难度，尊重选择。
- 首章剧情结束后接原有新手引导，不再叠一套召唤教程。未完成第一次操作时不提前放出剧情驱动的敌人。
- 章后主按钮指向下一推荐章，但先回到该章整备，不连续强行开战。
- 重试不自动重播完整章前。已见剧情可从“山海纪事”回看。

### 5.2 通关、已读与可回看必须分开

| 状态 | 唯一有效来源 | 不能这样做 |
| --- | --- | --- |
| 本章已通关 | 标准模式正式胜利记录 | 看完对白、杀死普通精英、点“下一章”就算通关 |
| 本场景已读 | 读到末页或主动跳过当前整场 | 已读就发奖励或升级难度权限 |
| 主线当前推荐章 | 从第一章起第一个未通关章节 | 用最后点击的地图索引覆盖 |
| 尾声开放 | 五章均通关 | 只要第五关胜利便无条件开放 |

难度解锁继续采用现有规则，剧情不另建第二份难度记录。

### 5.3 老存档与自由选关

- 从现有标准关 `completions` 推导已通关章节，不要求老玩家重打一遍。
- 例：只有第一、第三关通关，推荐第二关；第三关印记保留。第二关补齐后推荐第四关。
- 老玩家五关已通过，直接开放全部章后和尾声，显示“主线已贯通”，不自动从头播放。
- 自由守关允许越级；越级关卡的章前默认不强制播放，可在地图主动观看。战斗机制和奖励不变。
- 主线推荐入口按第一个未通关章节推进。自由守关在前置章节未齐时，开局只保留现有战术提示，不自动播放依赖前情的完整版章前。主动回看完整故事需标为“章节故事”，不伪造实际通关记录。
- 自由守关胜利照常计入对应章节。跨序补齐最后一章时，在结算后提示尾声已开放，不硬拼不合时序的过场。
- 自由跳关胜利默认只展示原结算和本章印记；章后故事由用户主动打开。尤其不得因为第五关胜利就自动播出五印共鸣；尾声仅在五章记录齐全时开放。
- 试炼、无尽、开发调试快捷胜利不能意外推进主线；调试若允许修改记录必须显式隔离测试存档。

### 5.4 成就与奖励

第一版用主线地图五枚印记和“山海纪事”收录提供进度反馈。“五境归名”只是主线完成标签，读取真实标准关通关记录；不另加成就 ID、奖励条件或羁绊权限。现有成就和妖灵解锁逻辑保持不变。

不奖励灵蕴、不奖励额外抽卡、不改变既有妖灵解锁；不把“看完不能跳的剧情”设成成就条件。Steam 成就 API 接入留在上架任务，不在这批实现。

## 6. 美术设计与资产清单

### 6.1 总体方向

**有体积感的现有异兽立绘，置于古卷岩彩的山川环境中。**

保留现有白泽的象牙白体色、金色角饰与青绿细节，保留饕餮现有辨识轮廓；不要每张图重新设计一次角色。背景可有绘画笔触，主体受光与投影必须一致。

最重要的视觉对比不是“怪物从丑变美”，而是同一外形从受束缚、失去回应，变成能够注视同伴、选择归路。浊气附着层必须与角色分开，不能用换成另一只更漂亮的异兽表达净化。

避免全篇黄纸滤镜：纸卷只是界面材质，不是所有章节的色调。也不要用现代霓虹、欧美重甲或写实真人明星脸替代山海意象。

### 6.3 交付技术规格

- 主画面构图为 16:9；母版建议 2560×1440 或更高。生成工具不支持精确尺寸时，先保留构图安全区，再规范导出，不假定工具能输出任意尺寸。
- 桌面运行图 1920×1080，移动图 1280×720；用 WebP 或经核对效果的 JPEG。透明叠层保留 PNG。
- 初始压缩预算：单张桌面图目标不超过 600 KiB、移动图不超过 300 KiB。质量不达标时先减少细碎噪点，再权衡预算，不以糊图达标。
- 章节图只保留当前和下一张解码驻留，1920×1080 RGBA 两张约 15.8 MiB；地图切入章节后释放无用解码引用。该估算仅含两张背景，不含角色叠层、纹理副本或游戏本身。
- 总运行故事资产目标不超过 8 MiB，移动首章新增请求目标不超过 1 MiB；需要实测，不能写成已达成指标。
- 画面四边留约 6% 安全区，下方约 22% 保留平缓明度给对白；不能把首领脸、印碑和归途灯火放在字幕后。
- 图中不生成标题、汉字、英文、按钮、数值和品牌标志。文字由界面单独渲染。
- 保存母版、提示词、参考资产路径、生成工具实际返回的模型标识与人工处理记录。不能把无法确认的模型写成“GPT Image 2”。
- 未压缩源图建议放 `G:\Codex files\shanhai-story-masters\`，提示词可放项目 `design/story-prompts/`；运行目录只放要加载的成品。
- 当前网页部署流程上传整个仓库，而桌面打包对部分源图/提示词已有排除规则。Terra 应核实两端各自清单，不能假定桌面排除规则也对网页生效。

1. 先完成第一章与第二章各一张样张，以白泽身份一致性和环境风格作为批准基准，再扩展其余章节。

3. 缩到手机横向可视区域后，仍能分辨主角、封印、威胁与道路。
4. 同一白泽角的数量、饰物、身体结构保持一致；不能靠“都是白色”算一致。

- 关键帧缩放范围 100%–103%，不做让人眩晕的快速推进。
- 不在对白时摇镜；战斗画布不因剧情过场改变坐标或保存缩放状态。
- 启用减少动态效果时，取消平移、缩放和描线，仅保留不超过 150ms 的淡入或直接切换。
- 跳过必须立即结束整个场景，取消剩余计时器与资源回调；不能跳过后迟到地切到旧章。
- 关闭界面、重开、加载存档后，旧动画回调不得再操作本局状态。

### 7.3 单局播放合同

1. 章前只在战斗初始化前播放，或在现有流程允许的非战斗阅读入口播放；不让敌人在不可见的画布里先走起来。
2. “守住此境”按钮与“跳过剧情后入战”使用同一个一次性启动出口；连续点击只初始化一次。
3. 波次短句随真实战斗事件显示，绝不增加准备时间或定格 3–5 秒。升级、抽签、技能操作的既有优先级不变。
4. 正式结算先完成真实奖励与进度处理。剧情入口随后开放，不以存档成功、图片加载完毕或动画完成作为结果页可操作的条件。
5. 完整故事线默认按序体验；自由选关玩家可忽略剧情。无论看完、跳过、回看还是图片失败，战斗同种子同操作应产生相同结果。

## 8. UI、触控与声音

### 8.1 章节地图

主体验是完整山海卷与五个清楚的地点，不做五张大卡片挤在战场上。当前位置与已完成位置通过印纹加文字双重识别，不只靠颜色。

选中节点后，在同一视野内提供章节名、难度与开始按钮；不再出现“选择关卡”和“开始守关”隔着长篇妖灵介绍的问题。妖灵信息仍留在图谱。

### 8.2 剧情阅读层

- 画面铺满可用剧情区域；正文落在底部低对比半透明带上，不套多层装饰卡片。
- 角色名在正文前，底部右侧为主动作，顶部可见“跳过剧情”。键盘与触控均可操作。
- 手机实测目标：正文约 16–18 CSS px 的实际屏幕等效尺寸，按钮触控区域至少约 44×44 CSS px；不要只在 1280 逻辑画布里设大字号后整体缩到不可读。
- 字体复用项目已有可用字体；不为剧情引入一个体积巨大的全量中文字体。
- 适配安全区、刘海、微信顶部栏和底部手势区。长句拆页，不挤压按钮。
- 旋转/缩放后检查按钮实际命中区与视觉位置一致，触控不穿透到战场召唤、出售或开始下一波。
- 现有项目有竖屏锁定浏览器的旋转壳适配。顶层 `dialog` 不可假定自动继承该旋转；实施时专门选择跟随壳的剧情层或显式处理顶层布局，并验证退出后的坐标恢复。
- 非战斗剧情不要求横屏 API 成功；华为 nova10pro、HarmonyOS 4.2、微信内打开是必须记录的真机回归场景。没有设备时只报告模拟验证，不能写“真机通过”。

### 8.3 音效与混音

| 事件 | 推荐声音 | 限制 |
| --- | --- | --- |
| 展卷 | 一次纸面摩擦加轻石磬 | 小于 0.8 秒，不每页重复 |
| 印记归位 | 短促低频石响与清亮尾音 | 小于 1.2 秒，不比首领音效更响 |
| 白泽恢复 | 一次柔和铃音 | 不与胜利音效同时满音量播放 |
| 五章完成 | 现有胜利主题的短尾奏或新短句 | 3–5 秒，可随退出停止 |

第一版不做全角色配音。复用现有音量、静音与用户手势解锁音频机制。浏览器拒绝播放时照常推进。连续点击不会叠出多层相同音效；背景音乐淡出应可取消，并在返回游戏时恢复正确状态。

## 9. 工程接入方案与风险

### 9.1 最小结构

建议新增 `src/story-data.js` 保存章节与文案，新增 `src/story-controller.js` 管理阅读游标、取消和展示。遵循当前普通脚本加载方式与 CSP，不为剧情引入框架或全项目模块迁移。

`src/main.js` 仅增加少量明确接点。不要复制整套战斗状态，不把现有 `state.mode` 粗暴增加为一个与 standard 并列、但漏接全部标准关逻辑的 story 模式。主线是标准守关的叙事入口。

数据示意，仅供实施参考：

```js
{
  id: 'c01',
  stageIndex: 0,
  title: '幽都·独守初印',
  introScene: 'c01_intro',
  outroScene: 'c01_outro',
  artwork: 'assets/story/c01-cave.webp',
  nextChapter: 'c02'
}
```

文本使用稳定场景 ID；战斗内事件单独按 ID 去重。不要用中文显示名称当存档键，不把 `fuxi` 与 `fuxi_long` 等现有不同 ID 混同。

最低数据合同还应声明：sceneId、发言者、正文、艺术资源键、触发事件、播放上下文与优先级。正文不能内嵌可执行回调。首领副名按 stageIndex + 敌人 ID + role 选择，仅作用于展示层；不要直接修改共享 `ENEMIES.baize.name` 一类定义，避免精英、图谱和其他模式名称一起被改。

### 9.2 接入位置与禁止事项

| 当前位置/流程 | 建议接法 | 主要风险 |
| --- | --- | --- |
| `startStandardGame` / 开始入口 | 选择主线后先处理章前；确认入战时调用一次原入口 | 章前尚未确认就丢弃可恢复战局；重复初始化 |
| `initGame` | 保持战斗初始化职责，创建新运行令牌后清理旧剧情事件 | 复用上局短句、定时器或点击回调 |
| `spawnFromGroups` / 末波清场后首领生成 | 真正生成 stageBoss 时触发一次副名与短句 | 波次一开始就播“首领出现” |
| 白泽复起分支 | 从实际复起事件发一次叙事提示 | 监听 HP=0 提前宣告胜利 |
| `finishGame` | 原有奖励与胜负一次性结算；结果页再提供章后入口 | 播完/跳过剧情再次调用结算，重复奖励 |
| `showScreen` | 使用已有屏幕切换约定或显式增加完整支持 | 仅传一个未支持的 story 名称导致所有页面隐藏 |
| `showGameDialog` / 暂停恢复 | 尊重已有暂停来源，剧情层不无条件设置 paused=false | 切程序、设置、剧情相互抢恢复权 |
| `resumeWaveGame` | 继续原战局，不重复章前、不改波次 | 故事开始流程覆盖恢复快照 |
| `saveProgress` / `createWaveSnapshot` | 加已读记录时保留合法断点；审查暂停状态下生成快照的行为 | 当前快照只在特定休整状态有效，剧情暂停时保存可能写入 null 丢掉原断点 |
| HUD 教程提示 | 复用原触发条件，白泽仅加署名；实际操作指令优先 | 诗化台词替换“点击/拖拽”说明后，玩家不知道怎么做 |
| 现有解锁与羁绊结算 | 读取原逻辑已产生的结果，决定是否显示包装短句 | 为符合剧情再次调用解锁、改卡池或强行激活羁绊 |

本表是接入风险审查，不是宣称当前已发生上述全部 Bug。Terra 必须用当前代码重新验证。

### 9.3 存档建议

只新增一个小而有版本的剧情元数据区，例如：

```json
{
  "story": {
    "version": 1,
    "seenScenes": ["prologue", "c01_intro"],
    "lastViewedChapter": "c01"
  }
}
```

- 已通关章节尽量从原标准关记录推导，不再维护一份可能不同步的 `clearedChapters`。
- `seenScenes` 仅接受已知 ID 的去重数组并限制长度；损坏时忽略剧情元数据，不丢弃战斗进度。
- 跳过可标记整场已读，但不会标记本章胜利。回看不会修改通关、积分、金币或抽卡随机数。
- 保存失败仍允许继续或退出；沿用现有保存失败提示和恢复机制，不能用写盘完成作为进入游戏的硬门槛。
- 不私自更改已有存档比较时序、版本号或桌面/网页优先级。新增字段跟随现有存档一起写入，不能新建一套互相抢覆盖的故事文件。
- 若无法安全保存已读而不丢失战局快照，先将已读保存在内存，延迟到现有安全保存点持久化；不能为了已读小功能冒险写坏断点。
- 清空存档与多槽位迁移需要覆盖新字段，但不在测试时清理用户真实存档。

### 9.4 不更改的系统

攻击、伤害、射程、速度、灵蕴、召唤概率、技能自动/手动优先级、转运签、难度门槛、既有妖灵解锁、双路部署、成长、敌人数量与出怪时序均不因剧情改变。

主线完成标签不进入原成就奖励系统；本识轮廓不进入敌人、妖灵、掉落或碰撞集合。白泽失联不得写入 paused、技能可用性或单位状态；只由剧情控制器决定是否显示对白。已有伤害/击杀术语无需全局改成“净化”，保持战斗信息准确。

若为了表达剧情必须更改这些内容，先停止对应小项并提交产品取舍，不擅自顺手平衡。

## 10. 性能、失败降级与可访问性

1. 懒加载当前章图，空闲时预取下一章；不在第一页一次解码七张大图。
2. 图加载失败使用现有背景或纯净底色，正文与操作始终可用。玩家无需等图片下载完才能跳过或继续。
3. 音频失败不影响状态机；窗口失焦不让剧情自动读完；回来保留当前页。
4. 每次退出、重开、恢复或章节切换递增场景令牌，过期异步回调直接失效。取消时解除监听，不堆积 RAF 或 setTimeout。
5. 正文、按钮使用可访问的文本与焦点顺序；返回后恢复焦点，不留下看不见的拦截层。
6. 剧情不能调用战斗 RNG；开启/关闭剧情的同种子测试，召唤和敌人结果应一致。
7. 在相同设备和画质下比较有无剧情后的战斗性能。结束剧情后不能持续做全屏滤镜或绘制隐藏背景；性能预算以仓库已有标准为准，不临时许诺所有手机 60 FPS。
8. 提交实际资源体积、首章加载耗时、开关剧情十次后的监听/内存趋势。内存单次数值不是泄漏证据，需观察稳定后的趋势。
